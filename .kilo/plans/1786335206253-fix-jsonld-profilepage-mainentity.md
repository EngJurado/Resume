# Fix JSON-LD ProfilePage mainEntity and WebSite name

## Problem
The validator reports:
1. `ProfilePage` missing required field `mainEntity`
2. `isPartOf` WebSite has name `"Carlos Mateo Jurado Díaz"` (a person's name, not a site name)

A previous fix (`.kilo/plans/1786331720586-fix-seo-spanish-title.md`) changed `buildJsonLd('Portfolio', ...)` → `buildJsonLd('Carlos Mateo Jurado Díaz', ...)`, which caused the WebSite name to become the person's name. This is semantically wrong for schema.org and triggers the validator error.

Additionally, `MainLayout.astro` contains a duplicate standalone `Person` JSON-LD object (lines 39-48) that conflicts with the `@graph` generated by `buildJsonLd`.

## Changes

### `src/utils/seo.ts`
- Rename parameter `title` → `siteName` (semantic clarity: this value is used for the WebSite name)
- No change to the `ProfilePage` structure itself — `mainEntity: { '@id': siteUrl }` is already correct
- The `Person` node already has `@id: siteUrl` so the reference resolves properly

### `src/pages/index.astro`
- Change `buildJsonLd('Carlos Mateo Jurado Díaz', profile.bio)` → `buildJsonLd('engjurado', profile.bio)`

### `src/layouts/MainLayout.astro`
- Remove the duplicate inline `Person` JSON-LD script (lines 39-48). The `SEO` component in `index.astro` already renders the full `@graph` including the `Person` node.
